# 作者简介 {.unnumbered}

LeisureLinux，B 站频道与微信公众号同名。长期做企业 IT 基础设施与基础架构，从 Unix 主机、数据库与数据中心运维，一路做到跨国团队的 IT 负责人与上市公司 CIO；近年的重心转向开源自建、家庭网关、DNS 与网络链的自主可控。

与这本书直接相关的一段经历，是在大规模企业环境里长期负责「名字与地址」这一层：

- 负责过跨地域数据中心的 7×24 基础架构运营，涉及高可用集群、容灾、容量规划与事件响应，也管过把数据中心整体迁移到另一地区的项目。那段时间最深的体会是：**故障往往不在某一台服务器，而在解析器、路由、缓存与人的排查顺序交界处**。
- 主导过大型企业办公网络与园区网络的基础架构，包含广域网线路、负载均衡、SSL VPN、企业无线、以及 DDI（DNS / DHCP / IP 地址管理）平台的选型与替换。DDI 这类系统平时没人注意，一旦解析不对，全公司都上不了网——本书反复强调的「先定位是哪一层在解析」，就来自这类现场。
- 长期维护 Unix / Linux、虚拟化与私有云环境（Solaris / AIX / Linux、VMware、Proxmox / KVM），也做过基于 WireGuard 的企业远程接入、多云备份与边缘网关。第 6 章的本地根区镜像、第 14 章按 uid 豁免出向 53、第 19 章的 IPv6 前缀轮换，都是这类自建环境里踩出来的坑。
- 写过面向 IT 服务的自动化与观测平台：资产自动发现、CMDB、监控与报表，以及把事件流程、升级路径和 SLA 固化下来的运营体系。本书坚持「每个配置都要有验证命令与回滚点」，是同一套工程习惯在写作里的延续。

技术写作之外，也做内容运营：B 站与微信公众号 *LeisureLinux* 主要聊 Linux、开源自建、家庭网络与 DNS。这本书不是官方文档的译注，也不是产品宣传；它把过去三十年在企业基础架构、以及近几年在自家网关上踩过的坑，整理成一套可复现的配置与验证方法。

读者构成上，本书面向有 Linux 运维基础、想自己搭或加固递归解析器的人。若你在企业里管过 DNS、在 Kubernetes 里被 `ndots` 绊过、或只是想让全屋设备的解析干净一点，书里的章节顺序应该能直接对上你的问题。

> 说明：本页只保留与基础架构、DNS 与运维写作相关的内容，不含任职单位、联系方式、教育背景、认证与具体项目规模等信息。书中所有示例环境均按第 1 章与「图书介绍」的约定脱敏，不对应任何真实生产网络。
