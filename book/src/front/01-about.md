# 图书介绍 {.unnumbered}

## 这本书讲什么

每一次联网都从一句提问开始：这个名字在哪里。DNS 把这句提问送出去，再把答案带回来，然后才有网页、支付、推送和视频。绝大多数人对它的了解止于「填一个递归解析器的地址」；而这本书关心的是地址填完之后发生的事——谁替你从根开始迭代、应答有没有在路上被改过、链路上有谁看得见完整查询名、缓存把旧答案留了多久、以及当加密端点不在自己手里时，本机那些策略还剩多少仍然生效。

书名点明了两条主线：**加密**解决「路上谁能看见」，**隐私防护**解决「这些看见能不能被收拢成一份关于你的档案」；而 Unbound 是贯穿全书的落点——一台边界清楚、只做递归验证、可以按角色拆成多个实例的解析器。从加固它说起，是因为所有抽象的判断最终都要落到一份能跑起来、能验证、坏了能退回来的配置上。

## 全书结构：五篇分别讲什么

**第一篇 认识 DNS 与 Unbound**（第 1–3 章）先把地基铺平：Unbound 为什么被设计成「不做权威服务器」，存根、缓存、转发、递归四种角色分别承担什么，以及 RD / RA / AD / CD 这些报文位到底在宣告谁的责任。这一篇不贴长配置，只建立后面所有章节共用的语言。

**第二篇 按角色配置 Unbound**（第 4–7 章）是动手的起点：十行起步的缓存解析器、单上游且 fail-closed 的转发器、带本地根区镜像的递归解析器（含 NSD 根镜像与按 uid 豁免出向 53），以及多实例下的端口规划、过滤表内存与 dnstap 观测。每个配置块都紧跟「为什么这么设」「一条可复制的验证命令」「失败模式与回滚点」三件事。

**第三篇 加固**（第 8–14 章）是全书最重的一篇。用 NIST SP 800-81r3 的框架画出信任边界，再逐层展开：最小暴露面与访问控制、DNSSEC 验证的三种状态、DoT 服务端、DoH 与 Web 服务共 443 的前端组合、查询名最小化与防降级、DDR 压制、以及加密通道选路与 nftables 劫持的边界。这里反复钉死一条区分：**DNSSEC 保证数据完整性与来源认证，DoT / DoH / DoQ 保证传输加密与链路隐私，两者不能互相替代**。

**第四篇 RFC 与协议理论**（第 15–18 章）回到条文，解释参数为什么是现在这个样子：基础 RFC 族、DNSSEC 族、加密与隐私族、以及 IPv6 / RA / RDNSS 在不同实现里的处理差异。理论为主，不重复贴配置。

**第五篇 工程实践**（第 19–37 章）收束到现场：IPv6 的 RA / RDNSS / ULA 与前缀轮换、Kubernetes 里的 DNS 选型与 `ndots`、anycast 集群与故障域隔离、DHCP 交接面、隧道与扫描这类攻击面、蜜罐与被动观测、以及一套六层的排查工具箱。第 37 章单独讨论 HTTPDNS——一种不属于 DNS 协议体系、却真实改变了 App 解析路径的形态，以及想用 Unbound 自建时该怎么搭。

## 为什么要讲安全加固

DNS 是 1983 年定下骨架的协议，默认明文、默认信任链路。一台配错的递归解析器会被拿去做放大攻击；一次上游瞬时 NXDOMAIN 会按负缓存规则被放大成小时级故障；一个 `qname-minimisation-strict: yes` 就能撞上违反 RFC 8020 的 CDN 区，让整站静态资源解析失败。这些都不是「参数没背熟」，而是**加固没做在正确的那一层**：缓存、验证、过滤、加密、故障域，每一层的失效方式都不同，排查时若在错误的层刷缓存、找 AD 位，就会白花一整天。

转发器上不配信任锚、多 `forward-addr` 是竞速不是主备、上游超时不许静默降级回明文 53、本机解析器进程的出向 53 必须按 uid 豁免——每一条都来自实际踩过的坑，也都给出回滚点。

## 为什么必须讲隐私防护

过去想知道一个人的行踪，得在他家门口装一台摄像头，或者用 GPS 跟踪他的行动轨迹。现在不需要了：**只要把他访问过的目标网站按时间排起来，就足以拼出他的作息、健康状况、财务往来、家庭关系与政治倾向**。而 DNS 查询正是这份清单的原始形态——它发生在任何连接建立之前，包含完整的目标名字，且默认不加密。

更关键的是，看见这份清单的往往不止一方：运营商的 LocalDNS、链路上任何一个被动观察者、被托付加密端点的服务运营者、以及自己门口那份没有设定保留期的 dnstap 日志。第 8 章的威胁模型把「谁看得见什么」逐条列出来；第 13、17 章讲查询名最小化、加密传输与 DDR 压制各自能挡住哪一段；第 12 章则提醒，把 DoH 端点放到别人的机器上，等于把本地策略一起交了出去。

**隐私防护不是锦上添花，而是这本书从「能跑」走向「可交付」的分界线。** 加密只保护一段链路，不保证数据来源可信；DNSSEC 只保证数据没被改过，一个字节都不隐藏。两者叠加，再加上把解析器握在自己手里，才谈得上「既不被偷看、也不被篡改」。这也是书名把「加密」和「隐私防护」并列的原因。

## 适合哪些读者

- **有 Linux 基础的入门者 / 家庭网关与自托管玩家**：想让全屋设备的解析干净、可过滤、可观测，且不想把查询交给第三方。从第 4 章十行起步，按篇顺序读即可。
- **运维与 SRE**：要在一台机器上跑多个解析器实例、按域名或信任域分流、处理上游抖动与缓存放大。重点看第 5–7、26、28、31、36 章。
- **安全工程师**：要画清 DNS 的信任边界、对齐 NIST 部署基线、判断加密传输与 DNSSEC 各自的覆盖面。重点看第 8–14、29、34、35 章。
- **Kubernetes / 云原生运维**：要理解 CoreDNS 与 Unbound 的分工、`ndots`、NodeLocal DNSCache 与出口验证。看第 20 章，再回第 3 章补角色划分。
- **移动端与 App 架构从业者**：关心 LocalDNS 劫持、精准调度、私有解析 API 与 SDK 改造代价。看第 32、37 章。
- **想读 RFC 但不知从哪下手的读者**：第四篇按族给出条文逻辑，可当索引用。

需要的基础：会看 `dig` 输出、能改 systemd 单元、知道 IPv4 / IPv6 子网是怎么回事。**不需要读过 RFC**，也不需要事先用过 Unbound。
