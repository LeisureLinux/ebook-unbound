# 前言 {.unnumbered}

## 为什么写这本书

DNS 是 1983 年定下骨架的协议。四十多年后，几乎所有联网动作仍要先问它一句"这个名字在哪里"。但绝大多数人对它的了解停留在"填一个公共递归解析器的地址"。

这本书不打算教你怎么填 DNS 地址。它要回答的是另一组问题：

- 一台机器上的解析器，凭什么相信拿到的答案？
- 从客户端到权威服务器，这条链上有谁看得见你在查什么？
- 把 DNS 加密之后，隐私就真的到手了吗？
- 为什么明明配置"看起来都对"，网站却打不开？

我们用过几乎所有形态：递归、转发、缓存、验证、加密前端、策略网关、IPv6 前缀轮换、无线路由通告、容器集群里的服务发现。也因此在每一层都踩过坑。有些坑的代价是一整天：为了在光猫里配一个 IPv6 DNS，把工作模式一改，ICMP 通、TCP 握手通、数据阶段静默丢包，此后所有"网站打不开"都被误判成别的问题。

**这些坑有一个共同点：它们都不在 DNS 教材里，而在解析器、内核、nftables 和路由通告的交界处。** 所以这本书的结构不是按功能罗列参数，而是按"角色 → 配置 → 加固 → 协议 → 工程"层层推进，并且每一处配置都配一句"怎么验证"和一句"坏了怎么退回来"。

## 这本书不做什么

- **不是官方文档的中文版。** NLnet Labs 的 Unbound 官方文档写得很好，且以 CC BY 3.0 开放。本书引用它、链接它，但不复述它。
- **不是任何英文书的翻译。** 市面上专门写 Unbound 的书极少；Jan-Piet Mens 的 *Alternative DNS Servers*（UIT Cambridge, 2008/2009）是第一本记录 Unbound 的书，作者 2010 年放出了无 DRM 的 PDF。本书把它当作史料与横评参考，不节录、不翻译其正文。
- **不是产品宣传。** BIND、dnsmasq、CoreDNS、NSD、PowerDNS、Knot Resolver 各有各的主场。书里会明确写 Unbound 不适合做什么。
- **不是合规清单的复读。** 第三篇会用 NIST SP 800-81r3 的框架建立威胁模型，但落点始终是可运行的配置与可观测的验证。

## 一个必须先说清的区分

全书反复用到这条分界，先在这里定死：

| | 解决什么 | 不解决什么 |
|---|---|---|
| **DNSSEC** | 数据完整性与来源认证：答案有没有被改过、是不是真的来自该区 | 不加密传输，不隐藏查询内容 |
| **DoT / DoH / DoQ** | 传输加密与链路隐私：旁人看不到查询内容 | 不验证答案真伪，不保证上游可信 |

两者叠加才构成"既不被偷看、也不被篡改"，但**任何一层都不能替代另一层**。混淆这两者，是很多"我已经上了加密 DNS 所以安全了"的根源。

同样要区分的是**谁在做验证**：存根解析器（操作系统里的那一小段）通常不验证，它把 RD 位置 1 丢给上游，然后看上游回的 AD 位。真正做验证的是递归解析器。把验证器放在链路的哪一层，决定了整条链的安全边界在哪里。

## 谁应该读

- **家庭网关 / 自托管玩家**：想让全屋设备的 DNS 干净、可过滤、可观测，且不想把查询交给第三方。
- **运维 / SRE**：要在一台机器上跑多个解析器实例，按域名或信任域分流，并处理上游抖动。
- **安全工程师**：要能画出 DNS 的信任边界，说清"谁看得见什么"，并对齐 NIST 的部署指南。
- **Kubernetes 运维**：要理解 CoreDNS 与 Unbound 的分工，处理 `ndots`、NodeLocal DNSCache 与集群出口验证。
- **网络爱好者**：想从 RFC 层面理解为什么某个参数是这样，而不是"教程里都这么写"。

需要的基础：会看 `dig` 输出、能改 systemd 单元、知道 IPv4/IPv6 子网是怎么回事。不需要读过 RFC。

## 本书结构

**第一篇 认识 DNS 与 Unbound**（第 1–3 章）
从 Unbound 的诞生讲起，把 DNS 基础与主流实现横评一遍，严格区分存根、缓存、转发、递归四种角色。第一篇不贴长配置。

**第二篇 按角色配置 Unbound**（第 4–7 章）
按角色分别给出缓存解析器、转发器、递归解析器 + 本地根镜像、多实例与可观测性的完整配置。每个配置块后面紧跟"为什么"、"怎么验证"、"失败模式与回滚点"。

**第三篇 加固**（第 8–14 章）
用 NIST SP 800-81r3 建立威胁模型，然后逐层展开：最小暴露面、DNSSEC 验证、DoT、DoH、查询隐私（QMIN / 防降级 / DDR 压制）、加密通道选路与 fail-closed 工程。这是全书最重的一篇。

**第四篇 RFC 与协议理论**（第 15–18 章）
这一篇**以理论为主**，不重复贴配置：DNS 基础 RFC 族、DNSSEC RFC 族、加密与隐私 RFC 族、IPv6 / RA / RDNSS RFC 族，以及同一组 RFC 在不同实现里的处理差异。

**第五篇 工程实践**（第 19–24 章）
IPv6 部署（RA、RDNSS、ULA、前缀轮换与临时地址寿命）、Kubernetes 中的 DNS 选型、一套完整的教学拓扑、以及十个真实故障案例的复盘。实战与理论在这里收束。

## 关于示例地址

本书所有 IP、域名、主机名、token 都是**教学用示例**，IPv4 取自 RFC 5737 文档段（`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`），IPv6 取自 RFC 3849 的 `2001:db8::/32`，域名用 `example.net` / `example.org`。任何与真实环境的相似都属巧合。

书中的实测数据（延迟、吞吐、计数器、失败率）来自一台家庭网关加一台境外云主机的实验环境，写进书里是为了说明**机制**与**量级**，不是性能承诺。你的链路、运营商与内核版本不同，数字必然不同。请以书里的验证命令在你自己的环境里重新测一遍。
